# Address PR Findings

Pull request **#{props.prNumber}** has open findings — failing status checks and/or unresolved
comments from human reviewers. Resolve them on the PR branch.

Findings to address (JSON; each has a `source` of `ci` or `human`, an `origin`, an optional `path`,
and a `body`):
{props.findings}

For each finding:

- **`ci`** — reproduce the failure locally, fix the underlying cause, and confirm the same command
  now passes. Do not paper over it by disabling, skipping, or loosening the check.
- **`human`** — if it is valid, fix it properly in the code (not a superficial patch), and add or
  update a meaningful test when the finding concerns behavior.
- If you deliberately do NOT act on a finding (you disagree, it's out of scope, or it's a false
  positive), do not change code for it — instead record it in `skipped` with a clear, honest
  `reason`. A human will read those reasons, so make each one defensible.

After fixing:

1. Run the project's tests/lint and make sure they pass.
2. Commit the fixes with a clear message referencing what was addressed.
3. Push to the PR branch (`git push`).
4. Capture the new head SHA (`git rev-parse HEAD`).

ABSOLUTE RULE: Do NOT merge the PR. Never run `gh pr merge`, never enable
auto-merge. Do NOT post comments on the PR and do NOT tag anyone.

ANONYMITY: Never name the tooling behind this work in the commit message or anywhere else others
will see it — no `xiv`, no `smithers`, no internal workflow or command names. It's a private
internal tool; the commit must read as ordinary human-authored work.

Report each addressed finding (with its commit) and each skipped finding (with
the reason), plus the new head SHA.

{props.schema}

Return ONLY raw JSON matching the required output schema.
