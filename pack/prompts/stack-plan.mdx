# Plan a Stack

Plan a **stacked-PR sequence** from the Linear source **{props.source}**.

`{props.source}` is either a Linear **project** (id or name) or a **parent issue** key
(e.g. `ENG-400`). Using the Linear MCP tools available to you (`linear` / `get_project` /
`get_issue` / `list_issues` / `list_comments`), do the following:

1. **Enumerate the work items.** `{props.source}` is a CONTAINER, not a work item itself.
   - If it is a **parent issue** (e.g. `ENG-3370`): call `list_issues` with `parentId: "{props.source}"`
     to get its **sub-issues**. The parent issue is NOT a stack entry — do not include it.
   - If it is a **project**: `list_issues` with that project to get its issues.
   Record the project id and/or parent issue key as provenance. You MUST end up with one entry per
   sub-issue/issue — never just the container. If `list_issues` returns nothing, say so and stop;
   do not return the container as the result.
2. **Order the issues into a stack**, bottom to top. The order is the sequence in which the
   issues should be built so each one stacks cleanly on the previous: foundational work
   first (schemas, types, contracts, data layer), then the pieces that depend on it
   (handlers, hooks, UI, wiring), then tests/polish. Respect explicit dependencies and any
   ordering implied by the issue descriptions or Linear sub-issue order. Every issue in the
   source must appear exactly once.
3. **Assign each issue a repo.** The available repo keys are: {props.repos}. Set `repo` on
   every issue to one of these keys. If there is only one key, use it for every issue. With
   several keys, infer the repo from the issue's labels, project/sub-team, or service named in
   its title/description (e.g. a "ledger" or Rust issue → the ledger repo). If an issue is not
   obviously tied to any repo, still pick the most likely key — assignment is refined later.
4. Capture each issue's key (e.g. `ENG-401`) and title. Do **not** invent branch names — the
   workflow derives those deterministically.

Do NOT write any code, create branches, or make repository changes. This is a read-only
planning step.

REQUIRED OUTPUT:
{props.schema}

Return ONLY raw JSON matching the required output schema, with `issues` in stack order
(index 0 is the bottom of the stack) and a `repo` key on each.
