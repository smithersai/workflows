# Read a PR's CI Status and Human Comments

Report the current state of pull request **#{props.prNumber}** on the two signals only GitHub can
supply: **status checks** and **review comments left by humans**. This is a read-only step — do NOT
modify code, do NOT comment, do NOT wait or poll, and NEVER merge.

Code review itself is not your job and is not happening here: it is done locally before the PR is
pushed. Do not review the diff, and do not invent findings of your own.

## Gather

Set `PR` to this PR's number — **{props.prNumber}** — then take a single snapshot. No sleeping, no
watching, no retry loop:

```bash
PR=<the PR number above>
OR=$(gh repo view --json nameWithOwner -q .nameWithOwner)
HEAD=$(gh pr view "$PR" --json headRefOid -q .headRefOid)
gh pr checks "$PR" || true                       # status checks (non-zero exit just means red/pending)
gh api "repos/$OR/pulls/$PR/reviews"             # formal reviews (state + body)
gh api "repos/$OR/pulls/$PR/comments"            # inline review (diff) comments — path:line threads
gh api "repos/$OR/issues/$PR/comments"           # issue / conversation comments
```

Echo the head SHA back in `headSha`.

## Classify CI

Set `ci` from the checks on the current head:

- `passing` — every check concluded successfully.
- `failing` — at least one check concluded in failure, error, timeout, or cancellation.
- `pending` — no failures yet, but at least one check is still queued or running.
- `none` — this PR has no status checks at all.

List the names of failing checks in `failingChecks`. For each failing check, add one finding with
`source: "ci"`, `origin` set to the check name, and a `body` that quotes the actual failure — the
failing test name, the compiler/lint error, the assertion — not just "CI is red". Pull the detail
from the run log (`gh run view <id> --log-failed`) when the check summary is not specific enough.
Leave `path` null unless the failure names a specific file.

## Classify human comments

A **human** comment is one from a real user account — not an app/bot account (a `[bot]` suffix or
`type: "Bot"`). Ignore bot comments entirely; no bot review is expected on these PRs.

For each human comment or review that raises something unresolved at the current head, add a
finding with `source: "human"`, `origin` set to their login, `path` when the comment is anchored to
a file, and the comment text as `body`. Judge "unresolved" against the **actual current code**, not
GitHub's resolved/unresolved thread flag: if the code already does what the comment asked, it is
resolved — skip it. A plain approval or an unqualified "looks good" is not a finding.

## Verdict

Set `clean: true` ONLY when `ci` is `passing` or `none` AND there are no findings. Anything else —
red or still-running checks, or an unaddressed human comment — is `clean: false`.
